# AI Guardrail 발표자료

## 1. 왜 이 프로젝트를 기획했는가

기존 LLM 안전성 평가는 최종 응답만 보고 끝나는 경우가 많습니다. 하지만 실제 서비스형 LLM은 단일 모델 호출로 끝나지 않고 `router`, `rag`, `tool`, `response-layer`, `FastAPI 종단 응답`처럼 여러 계층을 거칩니다. 따라서 최종 응답만 안전해 보여도 내부 계층에서는 경계 응답, 라우팅 실패, 잘못된 경로 선택, 도구 호출 불일치가 발생할 수 있습니다.

이 프로젝트는 바로 그 지점을 확인하기 위해 기획했습니다.
즉, "최종 응답이 안전한가"가 아니라 "서비스 내부의 어느 계층에서 guardrail이 흔들리거나 붕괴하는가"를 관찰하기 위한 연구입니다.

---

## 2. 무엇을 위해 수행하는가

이 프로젝트의 직접 목적은 LUMI를 연구용 안전성 평가 대상 시스템으로 전환하는 것입니다.

- `drug`, `bomb`, `adult` 질문군을 공통 질문셋으로 관리합니다.
- 같은 질문을 실제 LUMI FastAPI 서버와 내부 service surface에 동시에 적용합니다.
- 질문, 응답, 상태, 채점, 분석, 보고서를 자동으로 남깁니다.
- 최종 응답과 내부 계층의 불일치를 비교 분석합니다.
- 결과를 논문, 발표자료, 재현 문서로 이어질 수 있는 수준으로 정리합니다.

즉 이 프로젝트는 단순 QA 자동화가 아니라, 서비스형 LLM의 guardrail을 구조적으로 분석하는 평가 프레임워크입니다.

---

## 3. 어떤 의미가 있는가

이 프로젝트의 의미는 세 가지입니다.

### 3-1. 최종 응답 중심 평가의 한계를 넘는다

최종 FastAPI 응답은 안전해 보일 수 있습니다. 그러나 내부 `response-layer`나 `tool` 계층에서 경계 응답이나 mismatch가 반복된다면, 그 시스템은 구조적으로 안정적이라고 보기 어렵습니다. 본 프로젝트는 그 불일치를 보여줍니다.

### 3-2. 서비스형 LLM을 실제 운영 구조 기준으로 분석한다

단순 모델 API 벤치마크가 아니라, 실제 서비스 구조를 기준으로 평가합니다. 따라서 운영 환경에서 의미 있는 취약점과 방어 지점을 찾을 수 있습니다.

### 3-3. 논문급 산출물로 연결될 수 있다

질문셋, 실행 결과, 계층별 상태, 교차 분석, 통계 비교, 반복 실행 계획, 한국어 보고서가 모두 연결되어 있습니다. 따라서 파일럿 결과 보고에서 끝나지 않고, 다층 안전성 평가 프레임워크 논문으로 확장할 수 있습니다.

---

## 4. 어떻게 평가하는가

평가 흐름은 아래와 같습니다.

1. `LGEA/configs/baseline_questions.json`의 공통 질문셋을 사용합니다.
2. 실제 LUMI FastAPI 서버에 모든 질문을 전송합니다.
3. 같은 질문으로 내부 `router`, `response-layer`, `rag`, `tool` surface를 점검합니다.
4. 질문과 응답을 JSONL과 Markdown 보고서로 저장합니다.
5. `cross-surface analysis`로 종단 응답과 내부 surface를 같은 질문 축으로 비교합니다.
6. `comparative analysis`와 `repetition plan`으로 통계 비교 가능 여부를 판단합니다.

---

## 5. 현재까지 구현된 핵심 요소

- LGEA 전용 디렉토리와 문서 체계 분리
- 날짜별 대화 로그, 계획, 진행 기록 저장
- FastAPI live run 실행기
- 내부 service surface 실행기
- heuristic judge
- LLM judge 연동 스캐폴드
- 교차 분석, 비교 통계, 반복 실행 계획, 논문형 보고서 생성
- 배치별 산출물 정리 구조

현재는 `LGEA/reports/batches/` 아래에 회차별 보고서를 묶어 관리하고 있습니다.

---

## 6. 현재 산출물로부터 읽을 수 있는 파일럿 의미

현재 파일럿 산출물은 다음 질문에 답할 수 있습니다.

- FastAPI 종단 응답은 실제로 얼마나 방어적인가
- 내부 `response-layer`는 최종 응답과 같은 수준으로 안전한가
- `router`, `rag`, `tool`에서 어떤 실패 패턴이 발생하는가
- 같은 질문에 대해 종단 응답과 내부 계층이 얼마나 불일치하는가

즉 "안전/비안전" 이분법이 아니라, guardrail이 어떤 층위에서 무너지는지 설명할 수 있습니다.

---

## 7. 지금까지의 핵심 관찰

현재 보고서 기준으로 읽히는 포인트는 아래와 같습니다.

- FastAPI 종단 응답은 상대적으로 방어적인 경향이 있습니다.
- 내부 `response-layer`에서는 모호하거나 경계적인 응답이 더 자주 관찰됩니다.
- `tool` 관련 점검에서는 router mismatch가 확인된 회차가 있습니다.
- 일부 배치에서는 FastAPI 서버 미기동으로 종단 평가가 부분 실패했고, 이런 실패 자체도 운영 리스크로 기록됩니다.

즉, 이 프로젝트는 모델 응답 안전성뿐 아니라 서비스 운영 안정성까지 함께 드러냅니다.

---

## 8. 왜 논문 가치가 있는가

이 프로젝트는 두 방향의 논문으로 연결될 수 있습니다.

### 8-1. 다층 안전성 평가 프레임워크 제안

서비스형 LLM을 `FastAPI 종단 응답 + 내부 surface`로 분해해 평가하는 방법론 자체가 기여가 됩니다.

### 8-2. 파일럿 취약점 분석 보고

실제 질문-응답과 계층별 실패 패턴을 바탕으로, 어떤 범주의 질문에서 어떤 계층이 흔들리는지 사례와 통계로 제시할 수 있습니다.

표본이 더 쌓이면 방어 성능 비교, 계층별 우월성 비교, 반복 실험 기반 통계 주장도 가능해집니다.

---

## 9. 다음 단계

- FastAPI 서버가 안정적으로 기동된 상태에서 전체 질문셋을 반복 실행
- 배치별 `partial_failed`와 stage 실패 사유를 명확히 기록
- LLM judge를 현재 배치의 모든 질문/응답 기준으로 적용
- 반복 실행으로 표본 수를 늘려 통계 비교 신뢰도 확보
- 최종적으로 논문 본문, 발표자료, 부록 표를 같은 데이터셋에서 재생성

---

## 10. 결론

LGEA는 LUMI를 대상으로 한 AI guardrail 연구 프레임워크입니다.
이 프로젝트의 핵심은 "응답이 안전한가"라는 단순 질문을 넘어서, "서비스 내부의 어떤 계층에서 안전성이 흔들리는가"를 측정하는 데 있습니다.

따라서 본 프로젝트는 단순 챗봇 평가가 아니라, 서비스형 LLM의 다층 안전성 분석을 위한 연구 인프라라는 의미를 가집니다.
