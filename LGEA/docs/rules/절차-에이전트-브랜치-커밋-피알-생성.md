# 에이전트 브랜치 커밋 및 PR 생성 가이드

## 목적

- LGEA 작업을 브랜치 전략에 맞춰 일관되게 진행하고 PR까지 연결할 수 있도록 표준 절차를 제공합니다.

## 중요 원칙

- 단일 PR 단일 주제를 지킵니다.
- `pre-commit` 통과를 기본 조건으로 합니다.
- PR 제목/본문은 사용자 확인 후 생성합니다.
- PR milestone은 `LGEA-Phase-*` 체계 중 하나를 사용합니다.

## 브랜치 규칙

- 기준 브랜치: `main`, `dev`
- 기능 브랜치: `feat/lgea/<feature-name>`
- 수정 브랜치: `fix/lgea/<issue-name>`
- 기타 브랜치: `etc/<task-name>`

## 사전 확인

1. 현재 브랜치 확인: `git branch --show-current`
2. 작업 트리 확인: `git status`
3. 필요 시 `dev` 최신 상태 확인

## 변경사항 커밋

1. 변경 확인: `git status`, `git diff`
2. 신규 모듈에 단독 실행 진입점이 필요한지 확인
3. 관련 스크립트/모듈 실행 테스트 수행
4. 스테이징: `git add <path>`
5. `pre-commit` 검사 수행
6. 커밋:

```bash
git commit -m "feat: 변경 목적 중심으로 간결하게 작성"
```

## 원격 푸시

```bash
git push -u origin HEAD
```

## PR 생성 원칙

- `feat/lgea/*`, `fix/lgea/*`, `etc/*`는 `dev`로 PR을 생성합니다.
- PR은 단일 주제만 포함합니다.
- PR에는 milestone을 반드시 설정합니다.
- PR 생성 전 제목/본문 초안을 사용자에게 공유합니다.

## PR 본문 최소 템플릿

```md
## 연관 이슈
- Refs #<번호>

## 변경 내용
- 핵심 변경 1
- 핵심 변경 2

## 테스트
- [ ] 로컬 검증
- [ ] pre-commit 통과
```

## 체크리스트

- [ ] 브랜치 네이밍 규칙을 지켰는가
- [ ] `pre-commit` 검증을 통과했는가
- [ ] 변경 파일만 스테이징했는가
- [ ] milestone을 올바르게 선택했는가
- [ ] PR 제목/본문 초안을 사용자에게 공유했는가
