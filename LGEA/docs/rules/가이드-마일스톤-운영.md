# 마일스톤 운영 가이드

## 목적

- GitHub milestone을 LGEA 연구 단계와 직접 연결해 관리합니다.
- 이슈, PR, 연구 문서, 구현 단계를 동일한 phase 체계로 추적할 수 있게 합니다.

## 핵심 원칙

- milestone은 연구 단계 목표를 표현합니다.
- milestone 이름은 `LGEA-Phase-<번호>-<주제>` 형식을 기본값으로 합니다.
- milestone은 `Phase 1`부터 `Phase 5`까지 유지합니다.
- 세부 구현 이슈는 가능한 한 하나의 phase milestone에 연결합니다.

## 권장 milestone 체계

- `LGEA-Phase-1-Foundation`
- `LGEA-Phase-2-Persona-Baseline`
- `LGEA-Phase-3-Experiment-Pipeline`
- `LGEA-Phase-4-Evaluation-Analysis`
- `LGEA-Phase-5-Reporting-Thesis`

## phase 의미

### Phase 1
- 연구 범위 정의
- 문서/워크스페이스 구조 정리
- 페르소나 출처 인벤토리

### Phase 2
- 브랜치별 페르소나 정규화
- baseline plan 구성
- response-layer 평가 기준 고정

### Phase 3
- experiment matrix 생성
- runner / storage / scheduler 기반 구성
- 대량 실행 파이프라인 시작

### Phase 4
- Judge 자동 채점
- score 저장
- 통계 및 시각화

### Phase 5
- 논문용 보고서
- 재현 가이드
- 최종 산출물 패키징

## 선택 기준

- 문서/구조/인벤토리 작업: `LGEA-Phase-1-Foundation`
- persona loader, registry, baseline 관련 작업: `LGEA-Phase-2-Persona-Baseline`
- runner, matrix, storage, target client 관련 작업: `LGEA-Phase-3-Experiment-Pipeline`
- judge, scoring, analyzer 관련 작업: `LGEA-Phase-4-Evaluation-Analysis`
- report, figure, methodology, reproducibility 관련 작업: `LGEA-Phase-5-Reporting-Thesis`

## GitHub 메타데이터 기준

- milestone은 위 5개를 기준 집합으로 사용합니다.
- PR milestone은 연결 이슈의 milestone과 일치시킵니다.
- label은 milestone을 대체하지 않습니다.
- 저장소 description과 topics도 LGEA 연구 목적과 맞게 유지합니다.

## 체크리스트

- [ ] 현재 작업이 어느 phase인지 문서상 근거가 있는가
- [ ] 이슈와 PR에 같은 milestone을 연결했는가
- [ ] milestone 이름이 LGEA 단계 구조와 일치하는가
- [ ] phase 밖의 임의 milestone을 만들지 않았는가
