# AGENTS.md

이 문서는 `idol_agent_LUMI` 저장소 안의 `LGEA` 연구 워크스페이스에서 에이전트가 가장 먼저 확인하는 공용 진입점입니다.
`LGEA/docs/rules/` 문서는 LGEA 문서 운영, 브랜치/커밋/PR 절차, GitHub 메타데이터 기준을 정리한 로컬 규칙 집합입니다.

## 적용 범위

- 기본 적용 범위는 `LGEA/`와 `docs/LGEA/`입니다.
- 필요 시 루트 저장소 작업에도 참고하되, 실제 저장소 운영 규칙과 사용자 요청을 우선합니다.

## 작업 시작 순서

1. 요청을 문서 작업, 구현 작업, GitHub 운영 작업 중 하나로 분류합니다.
2. `LGEA/docs/rules/README.md`를 먼저 확인해 기준 문서를 선택합니다.
3. 선택한 문서의 절차와 체크리스트를 따라 작업합니다.
4. 완료 전 범위 이탈, 문서 정합성, 검증 결과를 확인합니다.

## 핵심 참조 문서

- 인덱스: `LGEA/docs/rules/README.md`
- 프로젝트 명세: `docs/LGEA/LGEA_projectspec.md`
- 단계 계획: `docs/LGEA/LGEA_phase_plan.md`
- 브랜치 운영: `LGEA/docs/rules/규칙-브랜치-운영.md`
- 커밋/PR 절차: `LGEA/docs/rules/절차-에이전트-브랜치-커밋-피알-생성.md`
- 이슈 생성 절차: `LGEA/docs/rules/절차-에이전트-이슈-생성.md`
- milestone 운영: `LGEA/docs/rules/가이드-마일스톤-운영.md`

## 문서 운영 원칙

- `LGEA/docs/rules/README.md`를 이 디렉토리의 단일 인덱스로 사용합니다.
- 파일명은 한글 기준, 하이픈(`-`) 구분을 유지합니다.
- 분류 접두어는 `규칙`, `가이드`, `절차`를 사용합니다.
- 문서 추가/이동/이름 변경 시 인덱스를 함께 갱신합니다.

## 전역 작업 원칙

- 기본 응답 언어는 한국어를 사용합니다.
- 추측보다 근거를 우선하고, 불확실하면 확인 필요 사항을 명시합니다.
- 기본 원칙은 최소 변경입니다.
- 민감정보(`.env`, API 키, 토큰)는 출력하거나 재노출하지 않습니다.

## Git/GitHub 운영 원칙

- 작업 브랜치는 `feat/lgea/*`, `fix/lgea/*`, `etc/*` 패턴을 우선 사용합니다.
- `main`, `dev` 직접 커밋은 금지합니다.
- 커밋 전 `pre-commit` 통과를 기본값으로 합니다.
- PR은 단일 주제 원칙을 지킵니다.
- milestone은 `LGEA-Phase-*` 체계와 연결합니다.
- GitHub 메타데이터 작업 시 description, topics, labels, milestones가 LGEA 현재 단계와 맞는지 먼저 확인합니다.

## 완료 점검

- 요청 범위를 벗어난 변경이 없는지 확인합니다.
- 문서 인덱스와 실제 파일 경로가 일치하는지 확인합니다.
- 테스트/검증 결과와 남은 리스크를 분리해 보고합니다.
