## 1. 사전 준비

### 1.1 Supabase 프로젝트 생성

- [Supabase Dashboard](https://supabase.com/dashboard)에서 프로젝트를 생성한다.
- 프로젝트 생성 후, Storage 메뉴에서 `company_storage` 버킷을 생성한다.

### 1.2 프로젝트 의존성 설치

```bash
uv sync
```

`supabase`, `httpx` 패키지가 `pyproject.toml`에 포함되어 있어 자동으로 설치된다.

## 2. 환경 변수 설정

`.env.example`을 복사하여 `.env` 파일을 생성하고, Supabase 대시보드에서 확인한 값을 입력한다.

```bash
cp .env.example .env
```

### 2.1 API Key 확인 경로

| 변수 | 확인 경로 | 설명 |
|------|-----------|------|
| `SUPABASE_URL` | Settings > API > Project URL | 프로젝트 URL |
| `SUPABASE_KEY` | Settings > API > anon (public) | 공개 키 |
| `SUPABASE_SERVICE_ROLE_KEY` | Settings > API > service_role (secret) | 관리자 키 (업로드용) |
| `ENDPOINT` | Settings > Storage > S3 Connection > Endpoint | S3 호환 엔드포인트 |
| `S3_ACCESS_KEY` | Settings > Storage > S3 Connection > Access key | S3 접근 키 |
| `S3_SECRET_KEY` | Settings > Storage > S3 Connection > Secret key | S3 시크릿 키 |

### 2.2 .env 파일 예시

```
SUPABASE_URL=https://<project_ref>.supabase.co
SUPABASE_KEY=<anon_key>
SUPABASE_SERVICE_ROLE_KEY=<service_role_key>
ENDPOINT=https://<project_ref>.supabase.co/storage/v1/s3
S3_ACCESS_KEY=<s3_access_key>
S3_SECRET_KEY=<s3_secret_key>
```

## 3. 파일 업로드

`outputs/` 폴더의 파일을 Supabase Storage의 `company_storage` 버킷에 업로드한다.

### 3.1 업로드 스크립트

```
script/upload_to_supabase.py
```

### 3.2 사용법

```bash
# 업로드 대상 파일 확인 (실제 업로드 없음)
uv run python script/upload_to_supabase.py --dry-run

# 전체 업로드
uv run python script/upload_to_supabase.py

# 특정 하위 폴더만 업로드
uv run python script/upload_to_supabase.py --subfolder products

# 기존 파일 덮어쓰기
uv run python script/upload_to_supabase.py --overwrite
```

### 3.3 한글 파일명 처리

Supabase Storage는 비 ASCII 문자(한글, 특수문자 등)를 파일 키로 허용하지 않는다. 업로드 스크립트는 다음과 같이 처리한다.

- ASCII 안전 파일명: 원본 이름 유지
- 한글/특수문자 포함 파일명: SHA256 해시(12자) + 확장자로 변환
- 각 폴더에 `_mapping.json` 파일을 함께 업로드하여 `해시이름 -> 원본파일명` 관계를 기록

예시:

| 원본 경로 | 스토리지 경로 |
|-----------|--------------|
| `products/document-parse.html` | `products/document-parse.html` (그대로) |
| `01_제품_소개/Solar Pro 3.json` | `eb8a9217dab3/f149e61d6474.json` (해시 변환) |

## 4. 스토리지 마운트 (rclone)

rclone을 사용하면 Supabase Storage를 로컬 파일시스템에 마운트하여 일반 폴더처럼 사용할 수 있다.

### 4.1 rclone 설치

#### Linux

```bash
curl https://rclone.org/install.sh | sudo bash
```

#### macOS

```bash
brew install rclone
```

#### Windows

아래 방법 중 택 1:

```powershell
# winget (권장)
winget install Rclone.Rclone

# scoop
scoop install rclone

# chocolatey
choco install rclone
```

패키지 관리자가 없는 경우 [rclone 다운로드 페이지](https://rclone.org/downloads/)에서 Windows용 zip 파일을 받아 압축 해제 후 `rclone.exe`를 PATH에 추가한다.

Windows에서 마운트 기능을 사용하려면 [WinFsp](https://winfsp.dev/)를 추가로 설치해야 한다.

```powershell
winget install WinFsp.WinFsp
```

### 4.2 rclone 설정

#### Linux / macOS

`.env` 파일의 S3 연결 정보를 사용하여 rclone 설정 파일을 생성한다.

```bash
mkdir -p ~/.config/rclone

cat > ~/.config/rclone/rclone.conf << EOF
[supabase]
type = s3
provider = Other
endpoint = <ENDPOINT 값>
access_key_id = <S3_ACCESS_KEY 값>
secret_access_key = <S3_SECRET_KEY 값>
acl = private
no_check_bucket = true
EOF
```

또는 `.env`에서 직접 로드하여 자동 생성:

```bash
source <(grep -v '^#' .env | grep -v '^$' | sed 's/^/export /')

cat > ~/.config/rclone/rclone.conf << EOF
[supabase]
type = s3
provider = Other
endpoint = ${ENDPOINT}
access_key_id = ${S3_ACCESS_KEY}
secret_access_key = ${S3_SECRET_KEY}
acl = private
no_check_bucket = true
EOF
```

#### Windows

설정 파일 경로는 `%APPDATA%\rclone\rclone.conf`이다.

```powershell
# 설정 디렉토리 생성
mkdir "$env:APPDATA\rclone" -Force

# 설정 파일 생성
@"
[supabase]
type = s3
provider = Other
endpoint = <ENDPOINT 값>
access_key_id = <S3_ACCESS_KEY 값>
secret_access_key = <S3_SECRET_KEY 값>
acl = private
no_check_bucket = true
"@ | Out-File -Encoding utf8 "$env:APPDATA\rclone\rclone.conf"
```

또는 `.env` 파일에서 값을 읽어 자동 생성:

```powershell
# .env 파일에서 변수 로드
Get-Content .env | ForEach-Object {
    if ($_ -match '^([^#]\S+?)=(.*)$') {
        Set-Item -Path "env:$($Matches[1])" -Value $Matches[2]
    }
}

# 설정 파일 생성
@"
[supabase]
type = s3
provider = Other
endpoint = $env:ENDPOINT
access_key_id = $env:S3_ACCESS_KEY
secret_access_key = $env:S3_SECRET_KEY
acl = private
no_check_bucket = true
"@ | Out-File -Encoding utf8 "$env:APPDATA\rclone\rclone.conf"
```

### 4.3 연결 테스트

```bash
# 버킷 내 폴더 목록 확인
rclone lsd supabase:company_storage/

# 파일 목록 확인
rclone ls supabase:company_storage/products/
```

### 4.4 마운트

#### Linux / macOS

```bash
# 마운트 디렉토리 생성
mkdir -p mnt/company_storage

# 백그라운드 마운트
rclone mount supabase:company_storage mnt/company_storage \
  --vfs-cache-mode full \
  --daemon

# 마운트 확인
ls mnt/company_storage/
```

#### Windows

```powershell
# 드라이브 문자로 마운트 (예: S: 드라이브)
rclone mount supabase:company_storage S: --vfs-cache-mode full

# 또는 특정 폴더에 마운트
mkdir mnt\company_storage
rclone mount supabase:company_storage mnt\company_storage --vfs-cache-mode full
```

Windows에서는 `--daemon` 옵션을 사용할 수 없다. 백그라운드 실행이 필요한 경우 별도 터미널에서 실행하거나, `nssm`으로 Windows 서비스로 등록한다.

```powershell
# nssm으로 서비스 등록 (선택)
nssm install rclone-supabase "C:\path\to\rclone.exe" "mount supabase:company_storage S: --vfs-cache-mode full"
nssm start rclone-supabase
```

### 4.5 마운트 해제

#### Linux / macOS

```bash
fusermount -u mnt/company_storage
```

#### Windows

마운트 중인 터미널에서 `Ctrl+C`로 종료하거나, 드라이브 마운트인 경우:

```powershell
# 작업 관리자에서 rclone.exe 프로세스를 종료
# 또는
taskkill /IM rclone.exe /F
```

## 5. 제한 사항 및 주의점

### 파일명 제한

- Supabase Storage는 파일 키에 비 ASCII 문자(한글, 공백, 특수문자)를 허용하지 않는다.
- 업로드 시 자동으로 해시 기반 ASCII 이름으로 변환되며, `_mapping.json`으로 원본 이름을 추적할 수 있다.

### 인증 키 구분

| 키 | 용도 | 권한 |
|----|------|------|
| `SUPABASE_KEY` (anon) | 클라이언트 접근 | 읽기 전용 (RLS 적용) |
| `SUPABASE_SERVICE_ROLE_KEY` | 서버 측 관리 | 전체 권한 (업로드/삭제 포함) |
| `S3_ACCESS_KEY` / `S3_SECRET_KEY` | rclone 마운트 | S3 프로토콜 접근 |

### 마운트 관련

- 마운트는 네트워크 I/O에 의존하므로 로컬 파일시스템보다 느리다.
- `--vfs-cache-mode full` 옵션을 사용해야 읽기/쓰기가 안정적이다.
- 시스템 재부팅 시 마운트가 해제되므로 다시 실행해야 한다.
- `mnt/` 폴더는 `.gitignore`에 포함되어 있다.
- Windows에서 마운트하려면 [WinFsp](https://winfsp.dev/)가 필요하다.
- Windows에서는 `--daemon` 옵션을 사용할 수 없으므로, 별도 터미널에서 실행하거나 `nssm`으로 서비스 등록한다.
