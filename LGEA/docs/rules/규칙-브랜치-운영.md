# 브랜치 운영 규칙

## 목적

- LGEA 연구 구현과 문서 작업을 `idol_agent_LUMI` 기본 서비스 작업과 충돌 없이 분리합니다.

## 브랜치 종류

- `main`: 운영 기준 브랜치
- `dev`: 통합 개발 브랜치
- `feat/lgea/<feature-name>`: LGEA 기능 구현 브랜치
- `fix/lgea/<issue-name>`: LGEA 수정 브랜치
- `etc/<task-name>`: 문서/운영/메타데이터 작업 브랜치

## 기본 작업 순서

1. `dev` 기준 최신 상태를 확인합니다.
2. 작업 시작 전에 목적에 맞는 브랜치를 만듭니다.
3. LGEA 관련 변경은 가능한 한 `LGEA/`, `docs/LGEA/`, `LGEA/docs/rules/`에 국한합니다.
4. 검증 후 커밋합니다.
5. 원격 푸시 후 `dev` 대상 PR을 생성합니다.

## 머지 기준

- `feat/lgea/*`, `fix/lgea/*`, `etc/*`는 기본적으로 `dev`로 머지합니다.
- `main` 직접 커밋은 금지합니다.

## 네이밍 규칙

- 브랜치 이름은 소문자와 하이픈(`-`)을 사용합니다.
- 연구 단계가 드러나도록 `baseline-pipeline`, `judge-scaffold`, `phase3-runner`처럼 목적을 명확히 적습니다.
